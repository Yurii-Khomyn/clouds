# Емулятор датчиків

Емулює три датчики різного типу й надсилає кожне вимірювання окремим `POST` на приймач.

| Датчик | Тип | Одиниця | Інтервал |
|---|---|---|---|
| `temp-kyiv-01` | `temperature` | °C | 40 мс |
| `hum-kyiv-01` | `humidity` | % | 70 мс |
| `light-kyiv-01` | `light` | lx | 100 мс |

Повідомлення (JSON):

```json
{
  "sensor_id": "temp-kyiv-01",
  "sensor_type": "temperature",
  "value": 21.37,
  "unit": "°C",
  "location": { "lat": 50.4501, "lon": 30.5234 },
  "measured_at": "2026-11-25T12:00:00.123Z"
}
```

Приблизно кожне двохсоте значення має різкий викид, щоб обробка мала що позначати як аномалію.

## Конфігурація

Файл `config.json` (адреса, датчики, їхні інтервали 20–100 мс) і змінні середовища, які його перекривають:

| Змінна | Призначення |
|---|---|
| `API_KEY` | Ключ доступу (заголовок `x-api-key`). **Обов'язкова**, у файлі не зберігається |
| `API_URL` | Адреса приймача (перекриває `api_url` з файла) |
| `DURATION_SECONDS` | Скільки секунд працювати; `0` або нічого: до зупинки Ctrl+C |
| `CONFIG_FILE` | Інший файл конфігурації |

Інтервал поза межами 20–100 мс емулятор не приймає й одразу завершується з помилкою.

Кожні 5 секунд у журнал пишеться кількість надісланих повідомлень і помилок (загалом і по датчиках), в кінці рядок `FINAL`.

## Локальна перевірка без хмари

```bash
cd lab3/emulator
API_KEY=test-key node mock-receiver.js        # термінал 1: локальний приймач
API_KEY=test-key DURATION_SECONDS=30 node index.js   # термінал 2: емулятор
```

## Запуск у Docker

```bash
docker build -t sensor-emulator lab3/emulator
docker run --rm -e API_KEY=<ключ> -e API_URL=https://<адреса приймача>/api/ingest \
  -e DURATION_SECONDS=300 sensor-emulator
```

Для демонстрації запускають на 5–10 хвилин (`DURATION_SECONDS=300`…`600`) і зупиняють.
