# Архітектура конвеєра

```
Емулятор (3 датчики)           Azure Functions (Flex Consumption)                 Azure
 ┌──────────────┐  POST        ┌───────────────┐   повідомлення   ┌──────────────┐
 │ temp / hum / │─────────────▶│ ingest        │─────────────────▶│ Service Bus  │
 │ light        │  x-api-key   │ (HTTP)        │                  │ черга        │
 └──────────────┘  202 / 400   └───────────────┘                  │ telemetry    │
                                                                   └──────┬───────┘
                                                                          │ тригер: нове повідомлення
                                                                          ▼
 GET /sensors/{id}/history     ┌───────────────┐                  ┌──────────────┐
 ◀─────────────────────────────│ history       │◀─────────────────│ process      │
        JSON-масив             │ (HTTP)        │     читання      │ (тригер SB)  │
                               └──────┬────────┘                  └──────┬───────┘
                                      │                                  │ запис (INSERT ON CONFLICT DO NOTHING)
                                      ▼                                  ▼
                               ┌──────────────────────────────────────────────┐
                               │ PostgreSQL Flexible Server (таблиця          │
                               │ measurements, Spain Central)                 │
                               └──────────────────────────────────────────────┘
```

Бонуси додають до цієї схеми:
- **Cosmos DB** (`raw`, ключ розділу `/sensor_id`): `process` паралельно зберігає кожне вимірювання в первинному вигляді; історію можна читати з нього (`?source=nosql`).
- **Blob Storage** (`camera`): камера отримує від функції `cameraUploadUrl` підписаний URL, завантажує знімок напряму в сховище, а в чергу йде лише ключ об'єкта.
- **Черга недоставлених** `telemetry/$deadletterqueue`: повідомлення, яке тричі не вдалося обробити.

Журнали функцій і метрики збираються в Application Insights (Log Analytics).

## Компоненти

| Компонент | Призначення | Файли |
|---|---|---|
| Емулятор датчиків | Єдиний звичайний процес: генерує вимірювання трьох типів і шле їх по HTTP | `emulator/` |
| Функція `ingest` | Публічний приймач: перевіряє ключ і формат, кладе повідомлення в чергу, відповідає `202`. Нічого не обробляє | `functions/src/functions/ingest.js` |
| Service Bus, черга `telemetry` | Буфер між приймачем і обробкою; повторна доставка; dead-letter після 3 невдалих спроб | `terraform/servicebus.tf` |
| Функція `process` | Тригер від черги: перевірка діапазону, перерахунки, аномалії, запис у базу (ідемпотентно) | `functions/src/functions/process.js`, `lib/processing.js` |
| PostgreSQL (Spain Central) | Зберігає оброблені вимірювання, індекс за датчиком і часом | `terraform/database.tf`, `functions/src/lib/db.js` |
| Функція `history` | `GET /sensors/{sensor_id}/history`, повертає масив у зворотному хронологічному порядку | `functions/src/functions/history.js` |
| Функція `cameraUploadUrl` | Видає підписаний URL (SAS) на завантаження знімка | `functions/src/functions/upload-url.js`, `lib/media.js` |
| Cosmos DB (serverless) | Сирі вимірювання для варіанта історії `?source=nosql` | `terraform/cosmos.tf`, `functions/src/lib/nosql.js` |
| Blob Storage | Знімки камери, доступ лише за підписаним URL | `terraform/media.tf` |
| Application Insights | Журнали виконання функцій | `terraform/main.tf` |
| Terraform | Усі хмарні ресурси та розгортання коду функцій | `terraform/` |

## Чому саме так

- **Нема постійно запущених контейнерів.** Усе, що виконується на стороні хмари, це функції, які запускаються подією (HTTP-запит або повідомлення в черзі) і оплачуються за виклик. Емулятор працює лише на час демонстрації.
- **Один HTTP-шлюз.** Функції `ingest` і `history` живуть в одному застосунку функцій, тож мають одну публічну адресу (`https://<функція>.azurewebsites.net/api/...`); ту саму роль, що API Gateway, виконує вбудований HTTP-вхід Azure Functions.
- **Приймач окремо від обробки.** Приймач відповідає за мілісекунди й не залежить від бази (див. `INGEST.md`).
- **Безпека.** Ключ доступу генерує Terraform (`random_password`) і зберігає в налаштуваннях функцій; у репозиторії його нема. Доступ до бази лише через TLS.
